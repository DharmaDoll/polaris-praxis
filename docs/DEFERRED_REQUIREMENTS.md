# Deferred Requirements — MVP 後の重要項目

## 1. 目的

現行 MVP を重くしすぎず、将来必要になる重要な仕様を失わないための管理表である。ここにある項目は現行機能ではなく、着手条件を満たした後に設計・承認する候補である。

優先度はこのアプリケーションの改善順序を示す。組織のセキュリティリスク優先度を示すものではない。

## 2. 管理ルール

- MVP の利用を阻害しない項目は、実利用の証跡が得られるまで実装しない
- 着手前に、対象となる失敗経路、低減するリスク、期待成果、残余リスクを定義する
- 実装を決定した場合は Initiative または Decision Record を作成する
- 完了した項目は成果物へのリンクを残して `Done` とする

## 4. 現時点の判断

まずは既存のMarkdown、YAML、テンプレート、プロンプト、Gitレビューと、依存の少ないローカル検証だけで運用する。正式Schema、CI、外部連携は、実利用から反復作業または品質問題が観測され、データ形式が安定してから追加する。

これにより早期利用を優先する一方、現行 MVP の残余リスクとして、入力ミス、参照切れ、承認権限の曖昧さ、証跡の陳腐化、ホスティング基盤への依存が残る。各リスクの Owner と受容可否は未確定である。
