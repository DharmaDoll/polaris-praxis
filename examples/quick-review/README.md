# チーム・機能別の半期評価サンプル

Product Security部内のAppSecチームが、上位方針に対してどの役割を果たしたか、次期に何を改善するかを考える例です。数値・組織・資料・承認はすべて架空（Synthetic）で、実組織の評価ではありません。

## 入力と出力を見比べる

1. [入力メモ](input.md)：上位方針、チームの役割、今期の目標・実績、次期の制約。
2. [評価案](generated/review.md)：会議で読む部分を先に置き、根拠と詳しい理由は末尾にまとめています。
3. [他の機能の目標例](team-goal-examples.md)：PSIRT、基盤、運用、対外説明、ガバナンス、教育にも置き換えられます。

この例では、目標・施策・活動量を分けます。

| 段階 | サンプルでの内容 |
|---|---|
| 会社・部門の方針 | 新機能を計画どおり提供し、顧客情報を守る。リスク判断を前倒しし、開発側の判断能力を育てる |
| チームの役割 | AppSecが要求・設計レビューと開発者支援を担う |
| チーム目標 | 重大な設計リスクを早期に判断・対処できる開発プロセスを定着させる |
| 重点施策 | 設計レビューを前倒しし、開発・製品責任者への判断の引継ぎを整える |
| 活動実績 | レビュー6件。件数だけで目標達成やリスク低減とは判断しない |

AppSecが期日内に判断材料を渡していても、製品側の処置決定が間に合わないことがあります。**チーム自身の担当成果と共同成果を分けて記述し、残るリスクと連携の改善点を評価に残します。**

## そのまま試す

このリポジトリを参照できるエージェントへ、次を渡してください。

```text
AGENTS.md、vision/、context/manifest.yaml、
prompts/12-results-to-next-year.md を読み、簡易レビューを行ってください。
今回の組織情報は examples/quick-review/input.md だけを使ってください。
入力はすべてSyntheticです。根拠のない事実や承認を追加しないでください。
対象はAppSecチームです。部門全体や個人の評価に置き換えず、
チーム自身の担当成果と共同成果を分けてください。
会議で読む評価案を先に、詳しい根拠を末尾にまとめてください。
完成例の generated/review.md は読まずに、
examples/quick-review/generated/trial-review.md に出力してください。
rootのContext、台帳、計画、Evidence等の正本は更新しないでください。
```

実行後に完成例と比べます。文章の一致ではなく、次を確認してください。

- 期日内に判断材料を返した成果を認めつつ、処置未決定のリスク1件を残しているか。
- 共同成果の未達をAppSecだけに帰責せず、連携上の責任も曖昧にしていないか。
- レビュー・勉強会の件数を、リスク低減や開発側の能力の証明にしていないか。
- 開発Aの確認済みの成果と、開発Bの未確認事項を区別しているか。
- 限られた工数で何を優先し、誰に判断・協力を求めるか示しているか。

## 資料がまだ揃っていない場合

[短い申告だけの入力](input-minimal.md)と[その評価案](generated/review-minimal.md)も見比べられます。依頼文の入力をinput-minimal.md、出力をgenerated/trial-review-minimal.mdへ変更すると試せます。通常版の入力や完成例は読ませません。

正式な達成条件・責任分担・証跡が未確認なら、整理と確認事項までは進めます。担当外の成果や、裏付けのない能力向上までチームの実績に加えません。

## 参照した活動体系

[DharmaDoll/AwesomeProductSecurity の OverviewDetail.md](https://github.com/DharmaDoll/AwesomeProductSecurity/blob/2c7f4057094157e884a1dfd9436e38b807aceecb/OverviewDetail.md)（参照日：2026-10-30、参照版：2c7f4057094157e884a1dfd9436e38b807aceecb）の機能区分を参考にしました。

参照先は活動範囲を考えるための資料です。このサンプルの組織構成・目標値・実績・承認の出典ではありません。割合のKPI例は採用せず、本PJの件数・時間・状態による測定ルールを適用しています。規制・ツール・成熟度に関する記述の採用や検証は、このサンプルの対象ではありません。

自分の業務で使う際は、[READMEの依頼文](../../README.md)へ自チームの情報を渡してください。目標値・責任分担をサンプルから流用せず、正式な承認と正本への反映は通常のDecision Gateに従います。
